## Reflection Questions

### 1. What did you do in this lab?
This lab I used ICMP to test network connectivity. I started the lab by using PC-1 to ping all the devices that uses IPv4 address to test each device connectivity. The first problem I came accross was PC-4 request timed out. So I went to PC-4 and used command ipconfig to see if the ip address, subnet mask, and default gateway were correct. The default gateway was misconfigured so I had to correct it to 10.10.5.1. Next problem was Server 1 but this time the ipv4 address was set on DHCP. Solution was to change DHCP to static then putting in the correct ipv4 address, subnet mask, and default gateway. The next and last problem I came accross was Labtop B destination host unreachable. I check ipconfig for Labtop B but the configuration was correct. So I checked the routers config and saw RTR-3 G0/0/1 ipv6 address was incorrect. Then when I changed the ipv6 address and used the command no shutdown. The ping to Labtop B was successful after the correction was made.

### 2. What did you learn?
I learn the importance of ICMP and how it helps me locate the connectivity issues. ICMP is an important tool for troubleshooting network issues, ensuring devices can communicate over a network. I learn the most common uses of ICMP is the ping command.

### 3. What did you struggle with or not fully understand?
I did struggle with that last problem I had with Labtop B. When I saw the configuration was correct it left me stumped. It wasn’t until later that I realized the problem could be with the routers.

### 4. What suggestions do you have to improve this lab experience?
I really enjoyed this lab since it was great using ICMP to test and troubleshoot network connectivity. It gave me a hand-on way to see how these tools help identify and fix issues in real time.
